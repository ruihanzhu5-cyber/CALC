# CALC V1 触发机制审查：学习“改变执行方式的收益”

日期：2026-11-01。本文是具体方法建议，不是实验结论；没有编辑运行代码、调用付费模型或使用标准答案作在线特征。

## 建议采用的一个机制

**Continuation-Advantage Trigger：继续执行增益触发器。**

每个真实工具结果返回后，用便宜的本地监测器更新可观测状态。对当前可执行的“分派动作 + 接收者 + 继续上下文”候选，预测相对于原样继续的**最终正确性变化**与**实际增量成本**；只有预计有正收益时才改变 Agent 的行动。否则继续当前执行路径。

核心是学习“在这个状态做这个干预，会比不做干预好多少”，而不是把角色熵、重复率等拼成一个人工加权告警指数。语义模型负责描述需要与可提供的信息、提出任务和上下文候选；本地小模型的触发依据来自真正跑到终态的成对继续轨迹。

## 别人具体怎么触发，我们借什么

| 工作 | 实际触发/适配机制 | 可借鉴之处与适用边界 |
|---|---|---|
| ATM | 每次 LLM 调用更新队列、上下文整理、工具错误、动作类别熵、重试和跨 Agent 等待六信号；固定加权 BI；前20 tick的95分位设阈值，连续3 tick超过才拆分。 | 可借遥测、历史校准和持续性。BI反映过载而不证明拆分有益；其主要评测含工具 stub、安全约束，不能直接当BC+收益证据。[原文3.2–3.3](https://arxiv.org/html/2607.20488) |
| POrchestra | Worker通过状态、请求与证据主动发起submit/revise/stop，交给编排者修改目标、上下文、工具或预算。 | 通信请求给出语义候选和干预时机，仍需判断此次干预的收益。[原文3.2](https://arxiv.org/html/2610.13485) |
| VoS | 对冻结前缀施加不同干预，继续到终态得到真实收益；训练价值函数并校准触发阈值，显式区分失败风险与干预收益。 | 这是触发器最重要的监督思想；移植到MAS时，候选必须包含接收者和继续上下文，而非只预测是否“需要帮助”。[原文4.1及附录C](https://arxiv.org/html/2610.09115) |
| DyTopo | 每轮让Agent生成need/offer描述，用MiniLM嵌入和余弦匹配形成稀疏有向通信边。 | need–offer是可用的匹配特征；高匹配只是“可能已有合适接收者”，不能独立决定reuse。[原文3.3、4.2](https://arxiv.org/html/2602.06039) |
| TacoMAS | 轨迹反馈支持快能力更新；每K轮由meta-LLM提出较慢的增删Agent、改边结构更新。 | 语义调整与较慢结构变化分开，避免频繁抖动；本项目的结构改变时点由实测收益学习，而不是照搬固定周期。[原文3.3–3.4](https://arxiv.org/html/2605.09539) |

以上均为论文方法摘述，不把作者的受限结果外推到我们的系统。ATM HTML页的日期字段与arXiv编号月份存在不一致，正式引用先用ID核对元数据，不据此宣称时间先后。

## 1. 可观测信号怎么定义

窗口可以从最近8个已完成工具步骤起步，窗口长度随后仅在训练/验证任务上选择。它是特征定义，不是“8步必须干预”。无需token log-prob；DeepSeek普通API返回、工具记录和共享工作状态足够。

| 信号 | 可计算定义 | 它不能证明什么 |
|---|---|---|
| 角色混合熵 | 对最近动作的实际目的标签取归一化Shannon熵 H=-Σ p(k)log p(k)/log K。标签来自已有任务/工具调用记录；未标注就保留unknown，不额外假造。 | 高熵可能是正常的搜索→核验→综合，不能直接推出spawn。工具类别熵也不是模型预测熵。 |
| 重复调查 | 归一化相同查询比例、已读docid再次读取比例、相邻检索结果docid重合度。语义近似重复可加本地小嵌入，但其成本须计入。 | 重读可能在核验矛盾，不能直接判低贡献。 |
| 未解决义务 | obligation总数、blocked数、连续步骤未变化数、已报告解决且附来源引用的数量。 | 模型报告“解决”只是可观测状态，不是正确性标签。 |
| 证据冲突/缺口 | 同一obligation下支持与反驳的引用对数；下一动作声明的required_refs中，接收者当前没有的比例。 | 引用存在不等于逻辑支持；这些是干预条件，不是reward。 |
| 上下文压力/整理 | 当前请求输入Token占模型输入空间的比例；活跃证据ID集合的增删比例；重组次数；恢复被移出内容的次数。 | 上下文长也可能有效；单纯压短不一定提高准确率。 |
| need–offer覆盖 | 候选接收者已持有的required_refs比例、其已处理obligation类型/任务描述与当前need的匹配度。 | 匹配高不保证接收后能继续，仍要考虑其本地上下文。 |
| 阻塞释放 | 相对上次checkpoint，新满足的依赖ID数、新到达证据/同伴结果数。 | 新消息不一定值得唤醒全部暂停Agent。 |
| 实际执行代价 | 已用API输入/输出Token、缓存命中、工具耗时、该分支的上下文长度和接收者剩余职责。 | 累计昂贵不等于从现在开始应终止；决策必须看未来增量。 |

标签与摘要最好附带在正常工具调用/Worker checkpoint中，不添加每轮一个“贡献裁判”的昂贵API请求。由runtime计算计数和匹配量；不编造底层API不返回的熵或logit。

## 2. 为什么是干预增益，不是失败诊断

同样的“高角色熵+高重复率”，至少可能有三种情况：

- 当前Agent即将通过反复交叉核验答对，此时spawn会分散注意力。
- 它在错误候选上循环，独立reverify可能救回正确答案。
- 它已经找到关键材料，只需收回Main综合；fold可能省成本而不损失正确性。

故“有问题”的标签不足以选择动作。为每个状态s及候选d，定义：

d = (operation, actor, recipient, obligation_ids, continuation_intent, selected_context)

ΔY(s,d) = Y(从同一前缀执行d后继续到终态) − Y(从同一前缀原样继续到终态)

ΔC(s,d) = C(d后的全部增量执行) − C(原样继续的全部增量执行)

Y来自官方BC+判分；C含所有Main、Worker、上下文整理、修复、候选构造及工具调用的真实费用/Token。缺usage须保留未知或下界。原前缀历史成本在两臂共享，单列而不重复叠加。

## 3. 怎么获得监督，而不重新造bench

先复现**CLM + BrowseComp-Plus + DeepSeekFlash**，冻结模型、工具、题目划分与评分协议。仅从训练题抽取可恢复前缀：

1. 从正常、失败和看似停滞状态都采样。混合均匀步骤采样与信号分层采样，不能只收手写告警已经触发的状态。
2. 每个前缀必须有continue对照，并随机覆盖至少一个可执行干预；必要时重复seed，避免把一次采样运气当因果规律。
3. 同一前缀的副本共享可见信息、模型、语料与已有执行状态；不同臂互不读取对方新结果。
4. 首阶段能学continue/spawn/reverify；reuse/fold/resume必须补充真实分派后状态，不能拿单Agent CLM前缀假装这些动作有训练覆盖。
5. 所有副本跑到真实终态并独立官方评分。只用前缀可见信号和候选上下文特征训练，gold/judge解释/未来结果均不进入在线输入。

第一批可以小规模验证采样与恢复能力，例如10训练题×3前缀×2臂；这只是采集烟测，不能支撑效果声明。后续按置信区间、动作覆盖和预算补充，避免一次要求VoS式数万继续轨迹。

这里的冻结前缀和成对干预是现有benchmark上的实验协议，不是新的benchmark贡献。

## 4. 在线触发如何执行

训练两个小型本地模型，输入x(s,d)包含上表信号、动作类型以及**候选接收者实际将看到的上下文特征**：

- f_Y(x) 预测ΔY；f_C(x)预测ΔC。
- 可先使用树模型或带动作交互项的回归；使用真实成对终态结果监督，权重从数据估计。
- 对任务分组的训练/验证划分做out-of-fold预测，校准“触发后伤害原本可成功轨迹”的频率与收益阈值。bootstrap/残差校准仅提供经验不确定性，不能宣称理论保证。
- 所有Agent共用触发器，actor ID不作为记忆具体题目的捷径；角色/职责描述可以作为上下文特征。

一个明确的准确率优先选择方式：

可接受集合 D_ok(s) = {d : calibrated_lower(ΔY_d) ≥ -ε}。

其中ε是验证集冻结的允许质量退化容差，不能在测试结果上调。对D_ok选预测效用最大的d，效用可写成预测ΔY − λ·预测ΔC/C_ref；若最大值未超过校准阈值τ，保持continue。也可直接公布不同ε、成本预算下的Pareto策略。

**λ是整个任务的质量/成本偏好，ε和τ是验证校准项；它们不是角色熵等信号的手工权重。** 论文需要报告这些偏好，并展示收益曲线。没有质量/成本偏好，不存在对所有场景都唯一最优的动作。

推理每次工具结果后只做小模型计算；不必每次额外调用LLM。语义候选来自正常任务模型记录的need、offer、obligation和继续意图，或其本来就发出的分派提议。候选若需额外API生成，必须计量且只在需要时调用，不能藏成“免费控制器”。

触发后提交所选d和它对应的上下文包。相同快照与相同候选不反复触发；只有新工具结果、依赖结果或指令变更才重新评估。这是去重调度，不是固定“高熵连续三次就拆分”的语义规则。

未训练/未校准时，该模块标为未训练；可进行数据采集，但不能用一组手写默认分数冒充学习型触发器。

## 5. spawn / reuse / reverify / fold / resume到底何时选

以下是应被价值模型区分的条件，不是再写一张人工if-else决策树：

| 候选 | 应学习的增益来源 | 与其他动作的关键区别 |
|---|---|---|
| spawn | 未解决need缺少合适现有接收者，独立上下文有助于新假设或不同证据路径，新增调用能改善终态。 | 即使角色熵高，已有peer更合适时也不应spawn。人数由任务产生。 |
| reuse | 某已有Agent的offer/已持证据匹配need，复用其本地状态比创建新上下文更便宜且有用。 | 不必重新让它调查已经拿到的证据；recipient和context必须一起评分。 |
| reverify | 关键结论有冲突、缺独立支持或可能锚定，挑战性继续动作能提高正确率。 | reverify首先是任务目的，可由新Agent或已有peer执行，不强制一种固定Verifier角色。 |
| fold | 独立分支继续的预测边际收益低，接收者拿到动作条件化胶囊后能保留质量并减少重复成本。 | 高累计成本不是终止理由；必须比较从现在开始继续或收回的增量结果。 |
| resume | 原暂停分支的依赖/证据已改变，重新使用其checkpoint比Main重新调查更有收益。 | 恢复的是保留的任务状态，不是再创建一个换名Worker。 |
| continue | 当前路径仍然最好，或干预价值不足以覆盖其费用与出错风险。 | 必须作为显式候选，防止系统为展示动态拓扑而频繁改队伍。 |

Main和Worker都能提出分派，既有peer也能接不同caller的工作。价值触发器作用于每个候选d；没有固定Agent数量或预设拓扑。

## 6. 保持一个强研究故事

主贡献可以表述为：**通过学习动作条件化的继续执行增益，决定未完工作何时移动、移给谁，以及接收者需要什么上下文。**

角色熵等信号负责描述状态；need–offer负责提出可能接收者；胶囊负责让该干预可执行；真正触发的是实测监督学到的相对收益。这是一条连续机制，不需要再添一个“熵模块贡献”、一个“拓扑模块贡献”和一个“摘要模块贡献”。

与VoS的差别必须落在联合候选的真实干预对象：它涉及不同执行者、可复用/可退休上下文和工作义务转移，而不只是在固定Agent上插一次纠正提示。与ATM的差别是触发目标从过载诊断变成正确性–成本增益；不把安全不变式或stub结果搬成我们的主结论。

## 最小验证

只保留三个关键对照：

1. CLM原样继续 vs 完整增益触发系统：官方正确率和全部实际成本。
2. 同一个分派/胶囊运行时，learned advantage vs ATM式遥测触发 vs 仅LLM提议：检验“何时行动”的贡献。
3. 同一触发器、同一候选接收者，joint context vs destination-blind capsule：检验触发收益是否依赖继续上下文耦合。

此外报告失败诊断AUROC与实际干预增益之间的关系，防止把“告警更准”当作“任务更好”。分派拓扑由执行记录重建，作为分析，不奖励无意义的架构复杂度。
