# CALC 研究与复现协议

日期：2026-10-31。状态：方法框架与实验协议，尚无正式 benchmark 性能结论。

## 研究主线

中心现象是协作价值随任务进展与信息分布变化。继续一个子代理、转交它的职责或关闭其执行循环，会改变后续可用信息；因此在状态 `s` 上共同选择 `(action, recipient, context)`，比较交接后的收益与全系统成本。

主张限于两个可检验命题：

1. CALC 相对强单代理、最新可比编排方法与固定小团队，改善任务质量和实际成本的 Pareto 前沿。
2. 联合选择相对独立生命周期与上下文组合具有额外收益，且可恢复交接减少职责或证据丢失造成的失败。

当前可解释评分器只是可运行初版；不是已校准的真实边际贡献、oracle 最优策略或学习完成的效用模型。实验若不支持上述命题，应限定结论并迭代机制。

## 方法不变量

- 工作项与 agent 分离，工作项有单一明确 owner；执行器可以关闭，未完职责不能无主。
- 证据保存稳定 ID、来源、版本与原文；摘要或输入视图不覆盖原始记录。
- 上下文编译保留任务、目标和未解决义务。强制内容放不进预算时显式报错，不能静默截断后声称交接完整。
- 生命周期操作在编译成功后才提交状态。编译或校验失败时，owner、agent 状态、历史和证据保持操作前状态。
- `transfer`、`merge`、`reassign` 提交指定职责与证据引用。部分交接不应关闭仍有职责的源 agent；全部交接后可归档其执行循环。
- `retire` 有未完职责时先交给指定接收者（默认 Main）；完成职责可以归档。`resume` 重新激活指定 agent，并明确重新分配的职责。
- 恢复使用保存的状态和原始历史，不伪造已经完成的工作，不重新执行不可重复的写操作。

## 基线复现顺序

1. 记录上游仓库、commit、依赖、原生入口、模型和配置；先运行公开小样本，核对工具和官方评分格式。
2. 保留原生基线输出，接入共同日志；迁移到不同模型属于迁移复现，不声称精确重现原论文数字。
3. 在独立 CALC 接口中接入任务状态、真实模型输入投影与交接执行器；原生基线不被原地改成弱版本。
4. 比较联合、独立组合及单模块模式，再围绕失败轨迹和贡献估计迭代。

优先读透并复现 2–3 个最强近邻，而非堆积弱对照。参考：[POrchestra](https://github.com/XueyangFeng/POrchestra)、[DCA](https://aclanthology.org/2026.emnlp-main.1785/)、[Spine](https://arxiv.org/abs/2610.37224)、[OneFlow](https://arxiv.org/abs/2601.12307)。不适配当前任务的方法应说明边界；启发式改写不能冒称其原版复现。

## 数据与 split

- 使用现成任务和官方评分，不修改目标或为提高分数移除失败任务。
- BrowseComp-Plus 可采用预冻结的研究者 `100 train / 100 dev / 630 test` 划分，须先核对总任务清单与任务簇；这不是官方 split，630 条分数不是全830 leaderboard 分数。
- GAIA2 若复用 POrchestra mini128 清单，固定其任务 ID、环境版本、重置状态和事件时钟，明确不是官方 full800。该迁移集不参与策略、阈值、packet 模板或 ranker 开发。
- train 用于可训练组件和反事实采样，dev 用于规则、预算档和超参选择，test 冻结后仅评价。所有同一原始任务的 checkpoint、分支和重复留在同一划分，近重复任务按簇划分。
- 若以后使用 AppWorld，遵守其[官方开发限制](https://github.com/StonyBrookNLP/appworld#-agent-development-restrictions)：train 可以训练，dev 用于调参和错误分析，test 仅 aggregate evaluation，不在 dev 拟合 ranker。

## 五个核心实验块

| 块 | 问题 | 主要比较 |
|---|---|---|
| B1 基线与闭环 | 最新基线可复现吗，职责与证据能真实交接吗？ | 原生基线、共同运行时基线、确定性行为测试 |
| B2 主结果 | 质量—费用/延迟前沿是否改善？ | StrongMain、POrchestra、Independent L+C、CALC；必要时同并发固定小团队 |
| B3 联合机制 | 联合选择是否超过单模块和独立组合？ | 固定、L-only、C-only、Independent L+C、Joint |
| B4 交接诊断 | 关闭执行循环时信息和职责如何保住？ | 继续、直接关闭、固定摘要交接、联合交接；仅合法训练/开发状态干预 |
| B5 冻结迁移 | 方法是否超出单模型与单任务环境？ | 第二模型、冻结迁移集、有限并发敏感性 |

2×2 只能说明两个组件是否有用，不能单独证明联合性。Independent L+C 与 Joint 共享状态、候选packet、工具、模型、调参和候选评估预算，区别在是否共同估计交接后状态。随机对照匹配调用或预算档，在线不能使用 CALC 的未来决定。

## 运行公平性与成本

- 共享模型版本、工具权限、可见信息、sampling、上下文上限、retry 规则、任务资源上限与核验器。
- 工具缓存、基础 Main loop 与证据存储不能只给 CALC；确定性只读缓存包含资源版本或失效条件，写操作后使受影响缓存过期。
- 先保留 POrchestra 原生单 active worker 语义；若 CALC 使用 K=3 并发，增加同 K 普通编排对照。总并发请求包含控制模型，episode 并发与模型请求并发分别记录。
- 统计 Main、worker、控制器、摘要器、在线 verifier、重试、已发出但取消的请求等全部 usage。输入、缓存输入、输出与计费推理 token 按 provider 可见字段保留。
- 实际模型费用按运行时锁定价格、缓存费率计算，检索/工具费用单列。核心 `estimated_tokens` 仅用于预算决策，不能替代真实 API token。
- 终局官方 LLM judge 属 evaluation cost，独立列账，不进入代理执行预算；在线帮助检索、选证据或调度的 judge 属方法执行成本。
- 端到端延迟按任务提交至最终结果计时，报告 mean、p50、p95；并行请求耗时相加不等于任务延迟。保留调用 span 以解释 critical path、排队与工具等待。
- 失败、超时、无输出包含在成功率与全体任务平均成本，不能只报告成功任务。基础设施故障的重跑规则提前冻结。

## 质量与统计

比较两种明确协议：固定同等预算上限时的成功率与实际消耗；开发集选好策略后，在相近质量下比较实际成本。预算上限相同不意味着每个方法必须用满。

统计单位是独立任务；任务簇聚类、seed 作为同任务重复测量。给逐任务配对差值、成功/失败四格表和聚类置信区间；不将多个 seed 当新增任务，不用两个独立置信区间是否重叠替代配对分析。

“差异不显著”不等于成功率保持。若声称非劣效，提前选定容忍度与主比较，并要求成功率差的单侧区间下界超过负容忍度；样本不足时报告不确定性和 Pareto 权衡，不反向放宽界限。小 pilot 用于排错、估方差与改方法，不设置庞大样本量作为开展研究的前置门槛。

## 首轮额度安排

约5,688次 rollout 是可调整上限模板，只有正式授权真实运行后才启动：主表3,032、关键第二seed656、额外消融300、随机100、预算档400、第二模型200、训练suffix800、训练前缀100、smoke/dev100。实际清单固定后复用同一系统结果，不重复计数。

800次suffix来自100个训练checkpoint×4候选×2重复，不代表800个独立任务或800个完整episode。另计产生checkpoint的前缀、评分与工具成本。若环境不支持安全快照，就完整重跑并重估费用，不伪造同状态反事实。

先用零样本/可解释评分跑通闭环，再按训练集动作差异决定是否拟合轻量ranker。checkpoint内pairwise质量偏好与成本回归是候选方案；控制器只能看到当前合法状态，不见真值、未来执行或终局分数。

## 结果发布门槛

每份结果绑定代码commit、上游pin、配置、任务manifest、模型版本、运行时间、真实usage与官方评价输出。确定性demo、mock HTTP、输出schema通过和环境检查均不能记作benchmark性能。未执行的比较标作计划，未通过的主张保留为假设。

共享环境和真实API可改变复现难度，任何限制应连同结果一起说明。需要暂停扩展的信号包括：控制费用吃掉节省、Joint不优于Independent、职责丢失、缓存过期造成质量下降；这些用于决定下一轮改进，不否定整个研究立项。
