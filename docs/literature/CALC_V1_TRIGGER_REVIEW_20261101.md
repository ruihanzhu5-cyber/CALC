# CALC V1 — literature mechanisms, checked 2026-11-01

## Scope and evidence

Primary publisher/author pages, arXiv versioned papers, and author repositories were searched. No connected Zotero/Obsidian tools or project-local PDF library were found; the arXiv helper was not available at the skill's fallback path, so official arXiv pages/HTML were used. This is a targeted mechanism review, not a systematic exhaustive review. Dates/venues below follow primary metadata; unreviewed papers are marked preprints. The first executable comparison is **CLM + BrowseComp-Plus**, using the same DeepSeek Flash backbone/tools/scoring protocol as CALC. Other papers inform method design; they are not an expanded first-round baseline matrix.

| [TacoMAS](https://arxiv.org/html/2605.09539), Xu et al., 2026 preprint | Fast trajectory-feedback memory/capability refinements; slower meta-LLM node birth/death and edge edits every K rounds. ## What should change in our design

The current V0 asks a rule scorer to choose continue/transfer with a context mode. The stronger V1 question is: **does this specific collaborative intervention, with this receiver and this context, improve continuation relative to carrying on here?**

Four decisions follow from the review:

1. **Observable event representation.** Preserve action-intent diversity, actual repeated tool requests, blocked work dependencies, conflicting source-backed claims, and progress on explicit task obligations. Source and status checks are runtime facts; semantic usefulness remains an estimate. Tool-category entropy alone is weak on BC+, where search/read dominate.
2. **Explicit alternatives.** At an event, compare continuing locally with creating a branch, reusing a peer, independent verification, information exchange, folding or resuming. Main and Worker have the same dispatch affordances. Agent count and graph are outputs, not prescribed inputs.
3. **Placement-conditioned context.** A dispatch contains actor, destination, return target, work IDs, next action, evidence/notes and return condition. A new fresh verifier may need task constraints and source references without an upstream conclusion; a resuming investigator may need detailed failed leads. The required input changes with the proposed action.
4. **Outcome-grounded improvement.** Initial API policy uses model reasoning plus these measurable signals. Training-only paired continuations and official terminal scores can later calibrate trigger utility. Self-reported confidence, novelty and model estimates are not ground truth. Do not present an untrained gate as a learned policy.

Proposed diagnostic feature families (our inference, not quotations from a paper): work-intent entropy and switching; repeated-search/document rate; unresolved/blocked obligations; new support/refutation of a candidate; need/offer alignment; receiver's source/context reuse; expected handoff size and actual model usage. We should learn which combinations matter rather than hand-sum these into a universal trigger threshold.

The decisive test is not a prettified team graph. On the same CLM/BC+ comparison protocol, measure official correctness and all actor/controller/repair tokens, then on the same V1 runtime compare learned/model-informed triggers against fixed-period and no-intervention controls. A diagnostic outcome may justify more agents for some tasks and fewer for others.
